# 玩家驻留、切前台与操作回执

2026-09-17 实现记录。本轮不修改 DBProxy 权威存储设计，不接入独立战斗服务。仍是单个 SlgWorldScene 的小规模、无鉴权 Demo，不是正式 PlayerHost 登录系统。

## 行为约定

- 玩家最近一次前台 RPC 后默认驻留 5 分钟。驻留命中使用服务器已确认内存状态，不重新 Load Redis/PG；资源按时间差补算，有变化仍需持久提交。因此“不读库”不等于“不写库”。
- 超期回收缓存；再次访问重新加载玩家记录。世界状态由本场景缓存，启动时加载世界及已登记玩家，恢复轻量截止时间索引；不能把启动扫描成本算成零。
- 建筑和行军使用方法名一次性 Timer，不再每秒轮询所有玩家。缓存回收不删除任务截止时间，玩家不回来也会尝试结算。粮食按需补算，不每分钟唤醒所有离线玩家写库。
- 抽卡结果放入独立 `receipt`，和可更新的战报 `report` 分开。只保存最新一条操作回执，不是完整事件历史。业务拒绝也占用序号并保存回执。
- 持久提交确认后才发布新内存状态。结果未知时保留原事务和操作号，后续先重试原事务，禁止重新抽卡或重扣款。数据库故障不能降级为内存成功。
- 普通建筑、抽卡等只提交玩家记录；首次登记、出征预留、到达占领等地图变化才原子提交玩家与世界。玩家各自互斥，地图操作另行协调，不再用整个场景的 busy 阻塞所有玩家。地图提交结果未知期间，其他地图操作会被拒绝重试，无关玩家操作仍可执行。

## 小程序切前台

当前 Cocos 适配 `Game.EVENT_HIDE/EVENT_SHOW`：切后台关闭旧连接、清除旧显示快照但保留未确认操作；切回来建立新连接、获取快照，再发送原未确认操作或玩家快照请求。仅收到序号和参数指纹均匹配的回执才清除 pending。连接代次隔离旧回调，旧响应不能覆盖新状态或释放新请求的 busy。

首版使用全量当前状态恢复，范围是本人状态和 Demo 的三个地块，不是未来整张 SLG 大地图。保活长短与客户端是否需要同步是两回事：服务端仍驻留，也需要让前端恢复最新状态。未实现断线期间增量事件补发。

旧 schema v1 存档可以没有 receipt，服务端返回明确的旧存档回执占位；旧未确认命令若没有可匹配回执，客户端不会擅自清除。这种升级窗口需维护处理，不能宣称任意旧 pending 已兼容。新协议、Model 和配置随构建发布并重启，不是仅替换 Hotfix。

这里只验证了生命周期处理代码，尚未在 Creator 或真实小程序后台/前台环境验收；不得据此声称微信登录、鉴权、断网恢复全部完成。

## 配置位置

手写文件：`modules/slg/src/model/residency.json`。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| keepAliveMs | 300000 | 最后前台请求后的驻留时间，不是断线后的会话 TTL |
| maxResidents | 32 | 驻留及在途加载的容量约束 |
| maxPlayers | 32 | 本世界最多登记开发玩家，目录不自动删除 |
| retryDelayMs | 1000 | 后台失败重试间隔 |
| maxTimerRetries | 5 | 后台连续失败达到上限后停止自动重试并保留任务/待确认状态 |

这是 **Model 构建期配置**，不是进程 JSON 动态参数，也不是 Luban 热表。修改后 `npm.cmd run build` 并重启。容量不足不驱逐活跃或待确认玩家；若把 maxResidents 调得小于 maxPlayers，离线任务也可能遇到加载容量限制。重试耗尽后需要原玩家请求触发恢复或重启，不能假定已自动恢复；应检查运行日志。

## 复测与证据

在 `packages/slg` 执行：

```powershell
npm.cmd run test:gameplay
npm.cmd run build
npm.cmd run smoke
node --test tools/recovery.test.mjs
```

`test:gameplay` 共 29 条：7 条规则、18 条实际 System 配假存储、4 条实际前台控制代码配模拟 Cocos。覆盖驻留零 Load、到期重读、只写受影响记录、回收后离线行军、启动恢复任务、抽卡回执不被战报覆盖、丢 ACK 原事务重试、不同玩家并行、地图互斥、未知提交保留、容量与有界重试，以及旧连接回调隔离。

本轮 29 条测试、模块检查、完整构建通过；真实数据库、真实小程序、500 玩家及长稳未重跑。之前 recovery-test.md 的数据库强杀结果属于修改前基线，不能直接当成本轮通过证据。后续应在新制品和隔离数据库上复跑，再谈容量和故障验收。

## 当前边界与接续工作

只有单世界权威拥有者，没有多进程租约/接管机制，禁止启动多个写入同一世界的权威场景。启动扫描、整份世界快照、32 玩家上限和免费演示随机数均不是生产容量/安全方案。下一轮优先验证新代码的隔离数据库恢复、真实小程序生命周期和长时间离线任务；不以修改通用 DBProxy 来替代游戏模块的状态所有权约束。

本轮工程教训：Model 引用的配置必须位于声明的 modelRoots 内；不要与基类私有 `timers` 字段重名，使用领域字段如 playerTimers。假的基类单测不能替代真实模块 typecheck/build，禁止为通过测试放宽引擎边界。
