# 七日问题对应的三组复测清单

2026-09-17。分析基线：[原始判断与代码核验](../../../TiangZ/docs/ai/external-7d-analysis-baseline-20260917.md)。本清单不代表测试已执行。外网旧报告保持原状，后续使用新run保存对比证据。

## 第一组：热更

- 原有负载和故障矩阵检查 Hotfix/config 成对切换、坏候选拒绝、排空超时、回滚；默认暂停窗口3000ms，RPC超时30000ms。
- 对比切换前、暂停中、恢复后请求：不能把时间窗口结束当成通过；必须核对已接收请求的结果、排队时长及RPC超时。
- 数据断言：单次业务只能使用一致的代码/配置版本；失败仍保持旧版本组合；恢复后不能遗漏或重复处理已接收请求。
- 主入口hotfix目前仍是独立夹具，不代表SLG真实建筑、抽卡在热更期间全部通过；真实DB子项和SLG热更业务交叉验收需另列证据，不能沿用夹具结论。

## 第二组：DBProxy故障

- 保留 PG、易失缓存Redis、可靠Redis、AOF、两个DBProxy节点的故障覆盖。
- 核心回归：先缓存版本N，提交N+1时让缓存写超时，保留可读的旧缓存；收到写成功后发起读取，断言不能得到N。需要在修复前后用同一受控场景复现。普通停机并重启空缓存不等价于此场景。
- 已新增 `postgres_redis::acknowledged_write_timeout_must_not_expose_old_cache`：使用 CLIENT PAUSE WRITE 暂停缓存写入，独立连接读取旧缓存，断言ACK后的revision和payload。归入原有 `postgres_redis --ignored` 契约阶段；先UNPAUSE再断言，自动暂停上限10秒。此用例已编译但尚未连接真实存储执行，当前服务可能失败；不得修改断言凑绿灯。DBProxy服务缺口本轮未修改。
- Rust soak 新日志保留读开始/结束时间、耗时、玩家及确认事务序号。SDK尚不提供实际endpoint和读取来源，记录未知，不能用配置端点冒充实际请求端点。
- SOAK_FINAL 分开记录 finalClientVisibleStatePassed、observedConsistencyPassed；后者旧读/缺失/不变量必须全零。两者都必须通过，旧二进制缺新字段时本地审计拒绝通过。
- 最终客户端检查不是完整SQL对账。保留本地控制器现有SQL快照、不可变事实、交易审计与Stream核对；对账覆盖范围必须随报告写明，不宣称已核查所有历史资产。
- 本地和外网Relay脚本改为分页读取；不因42段通过省略最终核验。读取失败、游标不前进、缺失和顺序错误均失败；至少一次投递允许按event_id去重，不能把传输重复当重复业务结算。
- Relay外网异常保留code/status/signal和stderr字节数，不输出认证信息。分页属于工具修正，不证明上轮失败就是64MiB缓冲溢出。

## 第三组：游戏进程崩溃恢复

- 原game是MMORPG进程拓扑，不会自动替换成SLG。SLG业务复测使用 `--suite slg`；两者报告分开，三类中的游戏类可按目标选对应入口。
- SLG现有小规模用例：建筑/行军提交前强杀、接受后恢复，抽卡/武将升级/战斗结算丢ACK，地块并发竞争、离线产出；依靠SQL和同操作重试断言不重复扣费、发卡或结算。
- 必须核对恢复后的资产和版本，不能只看进程存活；持久数据与地图数据分开对账。
- 此组保持DB运行，不能把存储故障混入游戏崩溃归因。三玩家正确性结果不代表500玩家容量验收。

## 共同比较和剩余准备

每次保留服务/测试器提交、dirty状态、实际二进制与脚本哈希、协议/配置身份、故障时间、恢复完成时间。正常、注入、恢复三个阶段分别评估错误和延迟；原有事件可用于离线关联，本轮没有新增完整分阶段统计器。

磁盘区分实际剩余、增长来源和未来保留预测；预测失败不得写成磁盘已满。最终报告同时列出主验收、Relay和资源检查，任何未核验项标记未完成。

复测前必须重新构建DBProxy soak，检查实际产物，先执行上述缓存回归夹具并确认捕获预期窗口。不要把本轮控制器单测称为故障复测通过。500玩家长稳和24小时不自动启动。
